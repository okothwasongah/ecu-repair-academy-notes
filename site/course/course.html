Unit 1: Engine Management System Architecture & Microcontroller Logic

Understanding the inner mechanics of the engine control unit is critical before reading or modifying internal flash memory.

1.1 Hardware Microarchitectures

  • TriCore Microcontrollers (Infineon TC1766, TC1796, TC1797, TC2xx, TC3xx): Found in Bosch EDC17, MED17, and Continental ECUs. Features internal flash memory, hardware security modules (HSM), and password-protected boot sectors.
  • Motorola/NXP MPC5xx (MPC555, MPC563): Found in Bosch EDC16 and Marelli units. Employs external flash chips (e.g., AM29BL802) and external EEPROMs.
  • STMicroelectronics (ST10F275, ST10F280): Found in earlier Bosch ME7 and Marelli ECUs.
  • Renesas SH705x / SH725xx: Common in Japanese platforms (Denso, Hitachi) found in Toyota, Nissan, and Subaru.

1.2 Memory Structures

Memory Type Stored Data Content Read/Write Characteristics
Internal/External Flash Operating system, engine calibration maps, fault codes (DTCs), emissions logic. Read/Writeable via OBD, Bench, or Boot mode. Holds map tables modified in WinOLS.
EEPROM (ST95xxx, 24Cxxx) Vehicle Identification Number (VIN), Immobilizer data, Injector coding, Odometer copies, Synchro bytes. Direct byte manipulation; critical for IMMO OFF, cloning, and virginizing functions.
Micro/Shadow ROM Bootloader execution code, factory processor configuration, OTP (One-Time Programmable) OTP zones. Generally read-only; contains factory security passwords.

Unit 2: Automotive Communication Protocols & Flashing Modes

2.1 Hardware Access Protocols

OBD Flashing (On-Board Diagnostics)

Reads/Writes flash via diagnostic port using ISO 15765-4 (CAN) or ISO 14230-4 (K-Line). Fast, but does not read full EEPROM or password sectors. High dependency on stable voltage.

Bench Mode (Service Mode)

Connects directly to ECU connector pins without opening the casing. Reads full micro flash and EEPROM via direct CAN/K-Line connection using factory boot passwords bypass.

Boot Mode & JTAG / BDM

Requires opening the ECU casing. Involves grounding processor boot pins or soldering JTAG trace pads to force processor into bootloader state for full unencrypted memory access.

Unit 3: WinOLS Map Identification & Calibration Engineering

3.1 Map Recognition & Data Structures

WinOLS displays memory dumps in Hexadecimal, 2D, and 3D views. Identifying maps requires recognizing axis structures, factors, offsets, and physical units.

Map Name Function & Characteristics Factor / Offset Example
Driver's Wish (Pedal Position) Maps accelerator pedal percentage and engine RPM to requested torque (Nm). Factor: 0.1 (Torque Nm), Factor: 0.01 (% Pedal)
Torque Limiters Caps maximum allowable torque output based on engine speed, atmospheric pressure, and transmission limits. 2D or 3D map array capping Nm output.
Smoke Limiter (Lambda / MAF) Limits fuel quantity (mg/stroke) based on air mass entering the engine to prevent unburned particulate smoke. AFR ratio calculation maps; critical for DPF/EGR tuning.
Rail Pressure & Limiter Controls Common Rail fuel pressure (bar) relative to engine load and RPM. Factor: 0.031250 or 0.1 to convert raw hex to Bar.
Boost Pressure & N75 Duty Cycle Sets target manifold absolute pressure (MAP) and controls Variable Geometry Turbocharger (VGT) vane position. Factor: 0.030518 or 1.0 (mbar)

3.2 Checksum Verification

Every ECU software block contains embedded Checksum (CS) algorithms (e.g., CRC32, RSA keys). Modifying calibration values changes byte sums. Flashing an ECU without recalculating checksums will result in an unbootable (bricked) engine controller.

Unit 4: Advanced Exhaust System Treatment & Calibration Workflows

Detailed technical analysis of emissions components, fault detection logic, sensor processing, and ECU calibration routines.

4.1 Exhaust Gas Recirculation (EGR) Systems

  • Mechanics: Recirculates inert exhaust gases back into intake air to lower combustion temperatures and reduce Nitrogen Oxide (NOx) emissions.
  • ECU Logic: Monitored via Mass Air Flow (MAF) drop when the valve opens.
  • EGR Recalibration Logic:
    • Set EGR Air Mass Target maps to maximum values across all RPM and torque points.
    • Zero out EGR Hysteresis Maps (2D maps that define duty cycle thresholds for valve activation).
    • Deactivate Diagnostic Trouble Codes (DTC switches) associated with valve position sensors and low flow faults (e.g., P0401, P0402).

4.2 Diesel Particulate Filter (DPF) Systems

  • Mechanics: Traps soot particles (PM10). Uses active regeneration by injecting extra post-combustion fuel to heat filter core to >600°C.
  • Sensors: Differential Pressure Sensor (Delta P), Exhaust Gas Temperature Sensors (EGTS - pre-turbo, pre-DPF, post-DPF).
  • DPF Recalibration Logic:
    • Locate and set the DPF Configuration Switch (Single byte or word logic switch, e.g., changing value 1 to 0 in Bosch EDC16/EDC17).
    • Disable Differential Pressure Sensor monitoring tables and model-based soot accumulation logic.
    • Zero out Post-Injection Fuel Quantity maps during post-combustion cycles to prevent oil dilution and high thermal stresses.
    • Clear specific DTC fault codes (P242F, P2002, P2453).

4.3 Selective Catalytic Reduction (AdBlue / SCR Systems)

  • Mechanics: Injects Diesel Exhaust Fluid (DEF / Urea) into exhaust stream ahead of SCR catalyst to reduce NOx into Nitrogen and Water.
  • Sensors: Upstream/Downstream NOx sensors, DEF Tank Heating elements, Urea Quality/Level sensors, Dosing module pressure sensors.
  • SCR Recalibration Logic:
    • Locate primary SCR Master Switch in software (e.g., Bosch EDC17 / MD1 software blocks).
    • Zero out SCR Dosing Quantity Request maps across all engine operating points.
    • Disable NOx sensor heating control loops and countdown lock-out counters in firmware.
    • Deactivate SCR system fault tables (e.g., P20EE, P203F, P204F).

4.4 Gasoline Exhaust Aftertreatment (CAT & OPF/GPF)

  • Cat-Off (Catalytic Converter): Disables secondary (post-cat) O2 sensor lambda monitoring routines and catalyst heating delay modes.
  • OPF/GPF Off (Gasoline Particulate Filter): Zeroes pressure differential triggers and exhaust temperature modeling maps on direct-injection petrol ECUs (Bosch MED17 / MG1).

Unit 5: Vehicle Immobilizer (IMMO) Protocols & EEPROM Editing

5.1 Immobilizer Functionality

Vehicle security systems establish a cryptographic handshake between Key Transponder -> Immobilizer Module / BCM -> ECU engine start enablement.

5.2 IMMO Modification Methodologies

IMMO OFF (Full Deactivation)

Direct modification of EEPROM (or Flash in modern ECUs) binary data to force ECU to bypass the cryptographic challenge and grant start authorization unconditionally. Required during engine swaps or lost key scenarios where immobilizer module replacement is obsolete.

Virginizing / ECU Renewal

Resetting internal EEPROM parameters (VIN, Component Security CS bytes, Secret Keys) back to factory unprogrammed state. Allows a used donor ECU to automatically adapt to a new vehicle's original immobilizer system using factory diagnostic tools.

Emulator Installation

Hardware module soldered into CAN/K-Line lines to continuously broadcast valid authorization frames to ECUs where software-only IMMO OFF is prevented by encrypted processor security routines.

Unit 7: Technical Procedures & Standard Operating Procedures (SOPs)

SOP 1: Comprehensive ECU Read & Backup Protocol

  1. Connect clean, stabilized power supply (13.8V continuous) to the vehicle battery or bench harness.
  2. Establish connection via OBD/Bench programmer interface.
  3. Perform automatic identification (ID) check to read SW/HW part numbers and seed keys.
  4. Execute a Full Read (Full Backup) containing Micro Flash, External Flash (if applicable), and EEPROM. Save unmodified file to secured storage.

SOP 2: Executing EGR & DPF Recalibration in WinOLS

  1. Import original raw .bin file into WinOLS. Verify checksum family match.
  2. Import corresponding DAMOS / A2L file or match hex patterns for ECU family (e.g., Bosch EDC17 C46).
  3. Locate EGR Hysteresis maps; set map values to 0 to permanently keep valve closed.
  4. Locate DPF Master Switch byte; modify value from 01 (Enabled) to 00 (Disabled).
  5. Search DTC Error Table using Hex/2D view. Locate fault codes related to differential pressure and EGR valve feedback; set error path values to 0.
  6. Perform physical filter honeycomb removal / EGR blanking plate installation to complete system reconfiguration.
  7. Recalculate file checksums, save modified .bin, and flash ECU using original tool interface.

SOP 3: Executing AdBlue / SCR Deactivation

  1. Perform full system diagnostic scan; reset all existing SCR fault timers and countdowns prior to ECU read.
  2. Read full Flash binary via Bench mode.
  3. Locate SCR Control Logic block and zero out target dosing maps and temperature threshold switches.
  4. Unplug physical SCR control module (DCU) or disconnect NOx sensors if required by ECU calibration type.
  5. Write modified software back to ECU; verify zero diagnostic trouble codes in OBD system.

SOP 4: IMMO OFF / EEPROM Editing Procedure

  1. Connect ECU on bench frame; access internal or external EEPROM using programmer (e.g., VVDI Prog, XPROG, KTAG).
  2. Read raw EEPROM binary data (e.g., 2KB / 4KB file).
  3. Load dump into specialized hex editor or IMMO calculation software.
  4. Locate immobilizer byte values (e.g., change specific offset logic bytes from 01 01 to 00 00 or modify status registers).
  5. Recalculate EEPROM checksum if required by ECU family.
  6. Solder or flash modified EEPROM dump back to board and verify engine start condition.

Emergency Brick Recovery Protocol

If an ECU fails to respond after writing (bricked due to wrong checksum, interrupted power, or corrupted flash): Do NOT cycle the ignition key or remove power if tool connection is still open. Attempt forced re-write using full original backup file via Bench / Boot Mode / JTAG interface to directly overwrite corrupt flash sectors.
